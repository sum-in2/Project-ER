# 전투 데미지 계산 공식 (Eternal Return 기준)

이터널리턴 데미지 공식을 구현 기준으로 정리한 문서.
실제 코드는 `IDamageCalculator`(분리 예정)에 격리하고, 인터페이스 설계는 system-design.md를 따른다.

출처: Eternal Return 공식 위키. 시즌4 이후 명칭 정리 기준.

---

## 공통 규칙

- 최소 피해량 = **1** (고정)
- 피해 증폭 최소값 = **0.1** (고정)
- 방어 상수 = **100** (롤과 동일)
- `(%)` 붙은 수치 = 비율 증감값(증폭), 안 붙은 건 고정값(추가피해)
  - 고정값 증가 = **추가피해**, % 증가 = **증폭**

코드 상수화 (매직넘버 금지):
```csharp
public static class CombatConstants
{
    public const float DefenseConstant = 100f; // 방어 상수
    public const float MinDamage       = 1f;   // 최소 피해
    public const float MinAmp          = 0.1f; // 증폭 최소값
    public const float CritBaseBonus   = 0.75f; // 기본공격 치명타 계수 (1 + 0.75 = 1.75배)
}
```

---

## 전체 구조 (평타·스킬 공통)

```
최종 피해 = (기본 피해 × 피해 증폭 + 피해 증가) × 최종 피해 증폭 × 모드 증폭
```

평타와 스킬은 **구조가 동일**하고 각 항의 출처만 다르다 → 다형(`IDamageProfile`)으로 분리, if/else 타입 분기 금지.

---

## 기본 공격 (평타)

| 항목 | 공식 |
|---|---|
| 적용 방어력 | `방어력 × (1 - 방어관통%) - 방어관통(고정)` |
| 기본 피해 | `공격력 × 100 / (적용방어력 + 100) × {1 + 치명타여부 × (0.75 + 치명타피해증가%)}` |
| 피해 증가 | `기본공격 추가피해 - 적의 기본공격 피해감소(고정)` |
| 피해 증폭 | `1 + 기본공격 증폭% - 적의 기본공격 피해감소%` |
| 최종 피해 증폭 | `1 + 최종피해 증가율 - 적의 최종피해 감소율` |
| 모드 증폭 | `모드별 주는피해 증폭율 - 적의 모드별 받는피해 증폭율` |

> 치명타 계수 주의: 기본공격 치명타 시 피해 **200% → 175%**. 그래서 공식에 `0.75`(= 1 + 0.75 = 1.75배)가 들어간다.
> 나무위키 0.75 / 고객센터 옛 문서 0.65 표기가 있으나 **공식 위키 기준 0.75가 최신**.

## 스킬

구조 동일, 항 이름만 변경:

| 항목 | 공식 |
|---|---|
| 기본 피해 | `스킬계수데미지 × 100 / (적용방어력 + 100)` (치명타 보통 없음) |
| 피해 증가 | `스킬공격 추가피해(고정) - 적의 스킬피해감소(고정)` |
| 피해 증폭 | `1 + 스킬 증폭% - 적의 스킬피해감소%` |
| 최종 피해 증폭 | 평타와 동일 |
| 모드 증폭 | 평타와 동일 |

---

## 방어력 핵심

감소율 = `방어력 / (방어력 + 100)`

| 방어력 | 감소율 | 실효 체력 |
|---|---|---|
| 100 | 50% | 2배 |
| 200 | 66.6% | 3배 |
| 300 | 75% | 4배 |

- 방어력 1당 실효체력 약 1% 증가(곱연산) → 무한대로 가도 100% 도달 불가.

---

## 구현 시 연산 순서 (중요)

```
방어관통 적용
  → 기본피해 계산 (치명타 포함)
  → 피해 증감(고정 항) 더하기
  → 증폭(%) 곱하기
  → 최종피해 증폭
  → 모드 보정
  → max(1, 결과)  // 최소 피해 1 보장
```

핵심: **고정값(추가피해)은 방어력 계산 후에 더해진다.**
- 고정 추가피해 → 방어력 영향 없음 (사실상 방어 무시 효과)
- % 증폭 → 방어력 계산된 값에 곱해지므로 방어력 영향 받음

---

## 구현 메모

- 치명타 굴림(`Random < 치명타확률`)은 계산기 밖(AttackState 등)에서 수행하고 `isCrit`만 주입 → 계산기는 순수 함수 유지(테스트 용이, GC 없음).
- 모드 증폭은 상황값 → 1차 구현에서는 기본 1.0(증가율 0)으로 두고 인터페이스 자리만 확보.
- 일부 스탯(치피/방관 등)이 ItemData에 아직 없으면 0 반환으로 시작.
- 서버 검증 설계와 동일 공식 사용 (데미지는 서버가 직접 재계산 — system-design.md "서버 검증 설계 원칙" 참조).
